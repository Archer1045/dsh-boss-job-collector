# 薪资提取验证结果

> 日期：2026-11-16
> 执行：阿渔（DSH）
> 复核：渔渔
> 结论：**字体还原路线已验证通过，15/15 全部正确；OCR 降级为备选**

## 1. 结论先行

`span.job-salary` 的文本是私有区码点（U+E031–U+E03A），由 BOSS 自研字体 `kanzhun-mix` 渲染。这层混淆可以直接还原，不需要 OCR、不需要截图、不调用任何接口。

- 字体文件只有 **1,288 字节、10 个字形**，从页面正常加载的资源里就能拿到。
- 映射是固定偏移：**数字 = 码点 − 0xE031**。
- 真实页面 15 条薪资全部还原为合理值，包括 `40-70K·15薪` 和 `500-550元/天` 两种格式。

因此原计划第 12 节「薪资需先验证可见区域 OCR」的前提（不逆向字体、改走截图 OCR）不再成立，建议改为主路径用字体还原、OCR 仅作降级。

## 2. 验证方法

1. 通过主人自己打开的浏览器（CDP 9222，只读执行 `Runtime.evaluate`，未刷新、未导航）读取当前搜索页。
2. 取 15 张 `li.job-card-box` 的 `span.job-salary` 原始 `textContent`。
3. 从 `performance.getEntriesByType('resource')` 取页面实际加载的字体 URL（样式表 `cssRules` 被 CORS 拦，资源列表不拦）。
4. `curl` 下载 woff2，用 `fontTools` 读 cmap，确认只有 10 个映射项、字形名无语义（`uniE031`…`uniE03A`）。
5. 用 PIL 把 10 个字形渲染成图，肉眼确认是标准数字 0–9。
6. 用还原规则处理全部 15 条，逐条核对合理性。

还原实现：

```js
const restoreSalary = (s) =>
  s.replace(/[\uE031-\uE03A]/g, (c) =>
    String.fromCharCode(0x30 + (c.charCodeAt(0) - 0xE031)));
```

字体文件：`https://img.bosszhipin.com/static/file/2023/3kovsijnt11693967587313.woff2`（1,288 bytes）。URL 里的 `1693967587313` 是 2023-09-06 的时间戳，说明是长期不变的静态文件，而不是每次请求动态生成。

页面上还有一个 `.../2022/16a48d9v961651026858984.ttf`，那是图标字体，与薪资无关。

## 5. 格式发现

薪资格式不止一种，解析器要同时认这三种：

| 格式 | 示例 |
| --- | --- |
| 月薪区间 | `20-30K` |
| 月薪区间 + 年终奖 | `40-70K·15薪` |
| 日薪 | `500-550元/天` |

## 6. 与 OCR 方案对比

| 维度 | 字体还原（本方案） | 可见区域 OCR |
| --- | --- | --- |
| 实测准确率 | 15/15（100%） | 目标 90%，尚未验证 |
| 运行依赖 | 无 | rapidocr + onnxruntime（约 100 MB） |
| 单条耗时 | 微秒级 | 50–200 ms（15 张 1–3 秒） |
| 需要截图 | 否 | 是 |
| 坐标/缩放问题 | 无 | 100%/125%、DPR、遮挡、视口外都要处理 |
| 隐私影响 | 只读 DOM 文本 | 截取页面像素 |
| 失效检测 | 结果合理性判断 | 置信度阈值 |

## 7. 插件侧要求

1. **码点还原**：适配器里按第 3 节规则替换，遇到 U+E031–U+E03A 就换成数字。
2. **结果合理性检查**（代替 canvas 像素自检，后者已验证不可靠——BOSS 字形与系统字体轮廓不同，比对命不中）：

   ```js
   // 合法形态之一，且数值区间合理
   /^\d+(?:-\d+)?(?:K|K·\d+薪|元\/天)$/
   // 下限 ≤ 上限，数值在 1–500 之间
   ```

   不满足时标记 `salary_unverified`，导出里不当作确定值。

3. **降级策略**：拿不到薪资文本或合理性检查失败时，薪资字段留空并带标记，不输出乱码，也不因一个字段丢弃整条记录。
4. **验收标准新增一条**：导出的薪资必须是可读数字，不能出现 `\uE035` 这类字符。

## 8. 未覆盖范围

- **映射变更场景**：只验证了当前这一个字体文件。如果 BOSS 换字体并打乱映射，还原会出错；靠第 7 节的合理性检查兜底，届时会表现为大量 `salary_unverified`。
- **其他页面类型**：验证的是搜索结果页。首页推荐位的卡片结构相同（已用保存的 HTML 确认），但薪资字段未逐条验证；职位详情页未测。
- **不同账号与地区**：只验证了一个账号、一个城市（北京）。未验证未登录状态（未登录时公司名会显示「某人工智能公司」，薪资是否同样混淆未测）。
- **历史字体版本**：只拿到当前版本，无法证明过去或将来的版本映射一致。
