# 薪资可见区域 OCR 验证计划

> 日期：2026-11-16  
> 状态：备选方案保留，当前不实施；字体还原已验证通过并成为主路径  
> 执行：阿渔  
> 复核：渔渔  
> 目的：确认 BOSS 直聘薪资在字体混淆情况下，能否通过用户可见区域 OCR 稳定提取。

## 1. 调研证据

当前样本：

- `D:\workSpace\code\「北京招聘」-2026年北京人才招聘信息 - BOSS直聘.html`
- `D:\workSpace\code\boss-job-collector\docs\_card-sample.txt`
- `D:\workSpace\code\boss-job-collector\docs\_probe.py`
- `D:\workSpace\code\boss-job-collector\docs\_probe2.py`

已确认：

1. 职位名、职位链接、公司、地区等字段仍可直接从卡片 DOM 提取。
2. `job-salary` 中是私有字符，而不是 `20-30K` 这样的明文，表现为字体反爬/字符混淆。
3. 保存页面中未找到明文薪资，也未找到可直接使用的 `window.__` 初始化薪资数据。
4. 页面加载了 `kanzhun`、`kanzhun-mix` 等自定义字体。
5. 因此，原计划“全部字段直接读取 DOM 文本”对薪资不成立，不能只靠修改选择器解决。

## 2. 调整原则

- 不逆向字体映射，不调用隐藏接口，不读取 Cookie 或内部响应。
- 普通字段继续走 DOM。
- 薪资只从用户当前实际可见的区域获取图像并识别。
- 用户主动点击时才执行，不自动翻页或批量截图。
- 在准确率验证通过前，不承诺输出结构化薪资。

## 3. 候选方案与优先级

### 方案 A：本地 OCR 服务（优先验证）

插件负责：

- 获取当前标签页可见截图。
- 根据薪资 DOM 元素的屏幕坐标裁图。
- 将裁图发送给阿渔侧本地 OCR 服务。
- 展示识别结果、置信度和失败原因。

本地 OCR 服务负责：

- 接收用户主动提交的薪资裁图。
- 识别 `K`、数字、连字符、`·薪` 等短文本。
- 返回结构化结果和原始识别文本，不保存图片。

优先验证 `rapidocr-onnxruntime`：部署相对轻，短数字和英文混合文本可先测 CPU 效果。使用项目独立虚拟环境，不直接安装进 ComfyUI 的 Python 环境，避免影响现有项目依赖。

### 方案 B：插件内 tesseract.js（备选）

优点是无需本地服务；缺点是包体、模型下载、速度和中文数字混排识别更复杂。只有方案 A 被证明适合而主人又不接受本地服务时，再单独验证。

### 方案 C：薪资截图导出（降级）

不识别文字，其余字段照常结构化，薪资保存为图片或占位标记。该方案只能作为降级，不视为结构化薪资验收通过。

## 4. 最小验证步骤

### 阶段 0：样本准备

- 从当前可见页面选取至少 10 个薪资元素。
- 覆盖 `20-30K·16薪`、`25-50K`、单数字起薪、不同位数和不同字体大小。
- 保存元素 DOM 坐标、对应截图和人工标准答案。
- 样本只含职位公开信息，不含账号或个人数据。

### 阶段 1：独立 OCR 冒烟

- 在项目独立虚拟环境安装 `rapidocr-onnxruntime`。
- 不开发插件，直接对裁图运行 OCR。
- 输出原图、识别文本、置信度和失败样本。
- 先验证 OCR 是否能识别，不讨论插件封装。

### 阶段 2：坐标与浏览器变量验证

- 验证 DOM 坐标和截图像素的对应关系。
- 覆盖浏览器缩放 100% / 125%、不同窗口宽度、不同 devicePixelRatio。
- 只截取当前视口内元素，不处理视口外卡片。
- 元素被遮挡、截断或不在视口内时明确跳过，不伪造结果。

### 阶段 3：结果格式校验

识别后统一检查：

- 是否包含数字和 `K`。
- 连字符和 `·薪` 是否保留。
- 是否把 `K` 误识别为 `k`，单位统一为大写 K。
- 是否出现明显不合理值，例如缺少全部数字、长度异常或多个薪资粘连。
- 低置信度结果进入人工确认，不自动写成确定薪资。

## 5. 验收标准

- 至少 10 个有效薪资样本完成识别。
- 普通清晰样本的完整字符串准确率目标为 90% 以上；若未达到，记录差距，不强行上线。
- `K`、数字区间和 `·薪` 的格式校验无误。
- 100% / 125% 缩放下的坐标映射正确，无裁错公司或职位名的情况。
- 遮挡、视口外和识别失败均有明确标记。
- 原图默认不保存，日志不包含账号或页面隐私信息。
- 验证结论明确区分：可进入插件开发 / 只能截图降级 / 需要更换方案。

## 6. 验证产物

建议写入：

```text
boss-job-collector/
└─ docs/
   └─ salary-ocr-validation-result.md
```

内容包括：

- 样本数量与格式。
- OCR 环境和依赖版本。
- 每个样本的标准答案、识别结果、置信度和耗时。
- 不同缩放与 DPR 的结果。
- 失败样本及原因。
- 最终方案建议与未覆盖范围。

## 7. 后续决策

- 达到准确率与坐标要求：原计划调整为“DOM 普通字段 + 本地 OCR 薪资”。
- OCR 可用但不稳定：薪资进入人工确认，不自动导出为确定值。
- OCR 不可行：第一版降级为薪资截图或空缺标记，不逆向字体、不调隐藏接口。
