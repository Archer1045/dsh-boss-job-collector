# BOSS Job Collector 执行计划

> 项目性质：独立的非官方浏览器信息整理插件  
> 文档版本：v0.1  
> 创建日期：2026-11-16  
> 当前状态：阶段 0 已完成，阶段 1 可开始  
> 实施：阿渔  
> 独立复核：渔渔  
> 目标平台：Chrome / Edge，Manifest V3

## 1. 项目概述

BOSS Job Collector 是一个辅助用户整理职位信息的浏览器插件。

用户在 BOSS 直聘网页上正常浏览职位搜索结果，点击插件后，插件读取当前页面中用户可见的职位卡片，提供结构化预览、手动滚动加载累积、去重以及 CSV / JSON 导出。

本项目不是自动爬虫，不代替用户浏览，不调用网站内部接口，不自动滚动加载，也不处理登录、验证码、设备指纹、请求签名或接口重放。

第一版的设计约束为：

- Manifest V3。
- 原生 JavaScript，不引入前端框架。
- 只适配 BOSS 直聘职位列表页。
- 用户主动点击时才扫描当前页。
- 只读取当前页面可见内容。

## 2. 背景与选型

目前没有找到可靠、公开、官方文档化的 BOSS 直聘职位搜索 API，因此不采用内部 JSON API、接口重放或浏览器自动化作为主要方案。

采用 Content Script 读取当前 DOM 的原因：

- 与用户已经看到的页面内容一致。
- 不需要模拟登录或携带账号凭据。
- 不产生额外搜索请求。
- 实现与部署简单，适合先验证字段和使用价值。
- 选择器和页面适配可以独立测试，后续维护成本可控。

## 3. 目标与非目标

### 3.1 第一版目标

- 扫描当前职位列表页的可见职位卡片。
- 提取职位名、薪资、公司、地区、经验、学历、职位标签、公司标签、职位链接、来源页和采集时间。
- 用户手动点击“扫描当前页”。
- 用户手动滚动加载后继续累积数据。
- 按职位链接中的稳定 ID 去重。
- 表格预览、删除单条、清空列表。
- 导出 CSV 和 JSON。
- DOM 结构变化时明确提示失效字段。

### 3.2 第一版不做

- 不自动滚动加载、定时抓取或批量关键词搜索。
- 不访问职位详情页或网站内部 JSON API。
- 不处理登录、滑块、验证码、设备指纹、请求签名或接口重放。
- 不采集简历、人才联系方式、聊天记录、Cookie 或隐藏字段。
- 不自动投递、打招呼或发送消息。
- 不做 AI 匹配评分。
- 不做多网站适配。

如果页面要求登录，由用户自行完成正常登录。插件只处理用户登录后主动打开并可见的页面。

## 4. 合规与隐私边界

### 4.1 数据边界

只处理当前职位卡片中用户可见的文本和链接，不读取：

- Cookie、LocalStorage 中的账号凭据或 Token。
- 网站接口响应和隐藏 JSON。
- 简历、人才联系方式、聊天记录。
- 与职位整理无关的个人信息。
- 页面完整 HTML 或可能包含隐私内容的调试输出。

### 4.2 行为边界

- 不自动滚动加载、自动搜索或定时采集。
- 不绕过登录、滑块、验证码、设备指纹、请求签名或访问限制。
- 不自动投递、打招呼、发送消息或执行其它写操作。
- 不通过降低访问频率来掩盖批量抓取，因为本项目本来就不做自动批量抓取。

### 4.3 开源样本边界

- 贡献的 HTML fixture 必须经过人工脱敏。
- 不提交真实账号、Cookie、Token、个人联系方式或聊天内容。
- 不直接复制 BOSS 直聘的图标、品牌素材、整页样式和大段受版权保护的文案。
- 页面样本只保留测试选择器和字段所需的最小结构，不追求完整镜像原站。

## 5. 技术结构

建议目录：

```text
boss-job-collector/
├─ manifest.json
├─ src/
│  ├─ background.js       # 打开侧边栏、消息转发
│  ├─ content.js          # 当前页扫描入口
│  ├─ boss-adapter.js     # BOSS 页面选择器与字段解析
│  ├─ panel.html          # 预览与操作界面
│  ├─ panel.js            # 累积、去重、删除、导出
│  ├─ exporters.js        # CSV / JSON 导出
│  └─ styles.css
├─ fixtures/
│  └─ boss-search.html    # 脱敏后的最小列表示例
├─ tests/
│  ├─ test-page.html     # 浏览器内选择器回归页
│  └─ assertions.js      # 无额外依赖的断言
└─ docs/
   └─ execution-plan.md  # 本文档
```

### 5.1 权限控制

仅申请实现功能所需权限：

| 权限 | 用途 |
| --- | --- |
| `activeTab` | 获取用户当前标签页 |
| `scripting` | 用户点击时注入扫描脚本 |
| `storage` | 保存已采集职位列表 |
| `downloads` | 导出 CSV / JSON |
| `sidePanel` | 展示预览表格 |
| `https://www.zhipin.com/*` | 限定可扫描的网站范围 |

不申请 Cookie、浏览历史、webRequest、代理、全部网站或其它与功能无关的权限。

### 5.2 页面提取策略

不要完全依赖容易变化的 CSS 类名，采用两层定位：

1. 通过 `a[href*="/job_detail/"]` 查找职位链接。
2. 向上定位最近的职位卡片容器，再解析卡片内字段。

`boss-adapter.js` 独立维护：

- 卡片定位规则。
- 字段选择器及优先级。
- 职位 ID 提取和 URL 规范化。
- 字段缺失诊断。
- 页面路径适配检查。

如果无法取得稳定职位 ID，不得用“职位名 + 公司”静默冒充稳定 ID。应记录规范化 URL，并向用户显示去重可靠性提示。

### 5.3 数据结构

每条记录建议采用：

```json
{
  "job_id": "职位链接中的稳定 ID",
  "title": "职位名",
  "salary": "20-30K·16薪",
  "company": "公司名称",
  "location": "北京朝阳区",
  "experience": "1-3年",
  "education": "本科",
  "job_tags": ["标签1", "标签2"],
  "company_tags": ["标签1", "标签2"],
  "url": "完整职位链接",
  "source_page": "当前列表页 URL",
  "collected_at": "ISO 时间"
}
```

只提取卡片内可见文本和链接，不读取脚本变量、隐藏字段或内部接口响应。

## 6. 分阶段实施

### 阶段 0：确认样本与字段

工作内容：

- 用户提供职位列表页的脱敏 HTML 或截图。
- 阿渔确认卡片结构、字段和职位 ID 来源。
- 渔渔复核样本不含个人信息、账号凭据和内部接口依赖。

完成标准：

- 字段清单确定。
- 职位 ID 和 URL 规范化规则确定。
- 页面路径、异常处理和脱敏规则确定。

### 阶段 1：插件骨架

工作内容：

- 创建 MV3 manifest、后台、侧边栏和扫描按钮。
- 仅在用户点击时向当前标签页注入扫描脚本。
- 非职位列表页显示明确提示，不执行提取。

完成标准：

- Chrome / Edge 开发者模式可加载。
- 权限与第 5.1 节一致，无多余申请。
- 不支持的页面有明确提示。

### 阶段 2：提取与去重

工作内容：

- 实现 BOSS 页面适配器。
- 将卡片转换为结构化记录。
- 使用 `chrome.storage.local` 保存累积结果。
- 设置容量上限，建议 1000 条。
- 重复扫描同一页不重复写入。

完成标准：

- 当前页提取数量与已加载到 DOM 中的职位卡片一致，不处理尚未加载的卡片。
- 重复扫描数量不增加。
- 用户手动滚动加载后能继续累积，链接和字段对应正确。
- 新卡片加载完成后再次扫描才合并结果；加载中给出提示，不把加载中的数量误当最终数量。

### 阶段 3：预览与导出

工作内容：

- 侧边栏展示记录。
- 支持单条删除、全部清空和手动刷新。
- CSV 使用 UTF-8 with BOM，方便 Excel 打开中文；JSON 使用 UTF-8 无 BOM。
- 转义双引号、逗号、换行和回车。
- 对以 `= + - @` 开头的内容做公式注入防护。
- 导出内容与当前预览一致。

完成标准：

- 预览、删除、清空和导出行为正确。
- CSV 中文不乱码，JSON 字段完整。
- 导出记录能追溯到职位链接和来源页。

### 阶段 4：回归与容错

工作内容：

- 用脱敏 fixture 做字段断言。
- 模拟缺薪资、缺公司标签、重复链接、无职位 ID 和 DOM 类名变化。
- 字段解析失败时显示具体字段和页面路径，不静默输出空表。
- 控制台不打印账号、完整 HTML 或隐私内容。

完成标准：

- 核心字段有回归断言。
- 缺失字段和页面变化有明确错误提示。
- 无静默重复、空结果或凭据泄漏。

### 阶段 5：人工验收与开源准备

工作内容：

- 用户实际打开职位搜索页操作。
- 阿渔记录版本、权限、实际结果和未覆盖范围。
- 渔渔独立复核选择器、去重、导出和权限。
- 编写安装、使用、限制、脱敏和 selector 更新说明。
- 确认开源许可证、非官方声明和贡献规范。

完成标准：

- 真实页面人工验收通过。
- 复核意见处理完成。
- 开源所需文档和样本检查完成。

## 7. 验收标准

### 功能

- 插件可在 Chrome 或 Edge 加载，无需额外后端服务。
- 扫描数量与当前已加载到页面中的职位卡片一致，不要求一次扫出未加载内容。
- 用户手动滚动到底部后，插件能识别新加载卡片并继续累积。
- 新卡片加载期间有明确状态提示，卡片数量稳定前不将扫描结果视为完成。
- 同一批已加载卡片重复扫描不重复，滚动加载前后重复出现的职位按稳定 ID 去重。
- 职位链接可点击，记录可追溯到来源页。
- 预览、删除、清空、CSV 和 JSON 导出一致。

### 可靠性

- 缺少字段时提示明确，不出现整页静默失败。
- 无法取得稳定 ID 时明确提示去重可靠性下降。
- fixture 回归通过，实际页面人工验收通过。
- CSV 中文不乱码，JSON 为有效 UTF-8 无 BOM。

### 安全与合规

- 没有自动请求、自动滚动加载、内部 API、Cookie 读取或绕验证行为。
- 除当前页面扫描和文件下载外，没有其它网络请求。
- 没有账号、Token、个人联系方式或聊天内容进入代码、日志、fixture 和导出文件。
- 权限与功能一一对应，无多余权限。

## 8. 风险与应对

| 风险 | 应对 |
| --- | --- |
| BOSS 修改 DOM 或类名 | 选择器独立到 `boss-adapter.js`，使用链接定位卡片并配 fixture |
| 动态渲染导致空扫描 | 用户主动点击扫描，不在页面加载瞬间自动执行 |
| 职位 ID 缺失或链接变化 | 规范化 URL，明确提示去重可靠性，不使用弱组合静默冒充 ID |
| 数据合规与隐私 | 只读可见职位信息，不接触内部接口、个人信息和账号凭据 |
| 累积数据过多 | 设置容量上限、单条删除和一键清空 |
| CSV 公式注入 | 对危险前缀进行转义，所有单元格按文本处理 |
| 开源样本泄露 | 最小化、人工脱敏、提交前复核 fixture 和日志 |

## 12. 方案定稿：字体还原为主路径，OCR 仅作备选

2026-11-16 样本调研发现，`job-salary` 使用私有字符和自定义字体，DOM 中不是可直接读取的明文薪资。后续验证已完成，结果见：

- `docs/salary-ocr-validation-result.md`
- `docs/salary-ocr-validation.md`（OCR 备选方案，保留但不占用当前工期）

验证结论：

- 当前字体只包含 10 个数字字形，码点 U+E031–U+E03A 与数字 0–9 一一对应。
- 映射规则为 `数字 = 码点 - 0xE031`。
- 真实搜索页 15 条薪资全部还原正确，覆盖月薪区间、年终奖和日薪。
- 该方式只处理页面公开字体和 DOM 文本，不需要截图、OCR、Cookie 或隐藏接口。

第一版采用：

```js
const restoreSalary = (s) =>
  s.replace(/[\uE031-\uE03A]/g, (c) =>
    String.fromCharCode(0x30 + (c.charCodeAt(0) - 0xE031)));
```

同时必须满足：

- 普通字段继续走 DOM，薪资格式化为可读文本。
- 支持 `20-30K`、`40-70K·15薪`、`500-550元/天` 三类格式。
- 导出前做格式和数值区间检查，下限不得大于上限，数值异常时不得当作确定值。
- 字体或映射变化导致检查失败时，字段标记为 `salary_unverified`，保留整条记录，不输出乱码。
- OCR 只作为后续降级备选，本批不实施；薪资截图可作为人工复核的辅助材料，不代替结构化文本。

阶段 0 的字段确认至此完成，可以进入阶段 1 插件骨架开发。
