# BOSS 岗位采集 二期执行计划：JD 采集与技能汇总报告

> 版本：v2.2 · 2026-11-16 · 一期已验收，本文件描述二期；含渔渔复核修订
> 主人已定三条：① 产出汇总成一份 md 文档；② 重点做 DSH 插件（换机器也能用），浏览器扩展冻结；③ 可用 LLM。

## 一、目标

一条指令产出一份报告：

> 帮我把现在这个 BOSS 页面的岗位连要求一起采集下来，汇总成一份技能分析报告

产出 `reports/boss-jobs-YYYYMMDD-HHmm.md`，里面包含：岗位清单（含薪资）、每条岗位的要求要点、技能频次表、按类别聚合、对「该补什么」的结论。

不做：投递、打招呼、改页面数据、绕过登录、自动翻页。

## 二、范围调整（相对 v2）

| 项 | v2 草案 | 现在 |
| --- | --- | --- |
| 主形态 | 浏览器扩展侧边栏 + DSH 插件 | **只做 DSH 插件**，扩展冻结在一期状态 |
| 汇总呈现 | 侧边栏区块 | **一份 md 文档** |
| 技能抽取 | 词典为主、LLM 兜底默认关 | 词典 + **模型直接读 JD 归纳**（不额外接 LLM 服务） |

理由：主人常在别的电脑上用，浏览器扩展要装扩展 + 加载解压目录，插件只要装 DSH 就有。

## 三、方案

### 3.1 采集：插件里点开详情面板读 DOM

```
collect_boss_jobs(withDetail: true)
  -> 对当前已渲染的每张卡片执行 click()
  -> 等右侧详情面板渲染（轮询，最多 3 秒）
  -> 读 JD 容器文本（含「职位描述」「任职要求」）
  -> 读不到就跳过该条，记 jd_error，不中断
  -> 节流 800ms 处理下一张
```

约束：

- 只处理当前已渲染卡片，**不自动滚动**
- 单次上限：`detailLimit` 默认 20 条（一次点太多容易触发风控）
- 用 `job_id` 定位卡片，不依赖坐标
- 每张都校验面板内容已切换（比对职位名），避免读到上一条

### 3.2 技能抽取：两层

第一层在插件里，规则词典（`src/skills.js`，约 80 条、六类）：

| 类别 | 示例 |
| --- | --- |
| 编程语言 | Python、Go、Java、TypeScript、SQL |
| Agent 与编排 | LangGraph、LangChain、ReAct、Planning、Checkpointer、HITL、MCP、Tool Calling |
| 模型与算法 | RAG、微调（LoRA/SFT/DPO）、Embedding、Reranker、向量库 |
| 工程基础 | FastAPI、异步、数据库、Docker、K8s、消息队列 |
| 评测与质量 | RAGAS、评测集、Bad Case、召回率、幻觉 |
| 领域与加分 | 金融、量化、因子、行情、开源、论文 |

输出 `skills: [{ name, category, hits }]`，别名归一（`rag` / `RAG` / `检索增强`）。

第二层是我（对话里的模型）：拿到 JD 原文后归纳词典没覆盖的表述，写进报告。不额外接 LLM 服务，省一层依赖。

### 3.3 报告：由模型写，格式固定

```markdown
# BOSS 岗位分析：<关键词> · <日期>

## 概览
- 采集时间 / 页面 / 条数 / 有 JD 的条数
- 薪资区间分布

## 岗位清单
| # | 岗位 | 公司 | 地点 | 薪资 | 要求要点 |

## 技能频次
| 技能 | 类别 | 岗位数 | 占比 |

## 分类聚合
六类各有多少岗位提到

## 结论
这类岗位最看重的 5 项能力，以及缺口建议
```

报告由我写（我有文件写入能力，也最懂怎么组织），插件只负责把结构化数据交出来。

## 四、分阶段

### 阶段 0：详情面板调研（30 分钟）

- `.tmp/probe-detail.mjs`：CDP 点开第一张卡，dump 面板 DOM
- 确认：JD 容器选择器、是否有独立分段、关闭方式、是否会跳新 tab
- 产出 `.tmp/detail-probe.md`

### 阶段 1：插件采集详情（1.5 小时）

- `dsh-plugin/src/detail.js`：`openCard(jobId)` / `waitPanel()` / `extractDetail()` / `closePanel()`
- `dsh-plugin/src/collect.js` 增加 `withDetail` 与 `detailLimit`，串行 + 节流 + 失败跳过
- `index.js`：工具参数加 `withDetail`（默认 false）、`detailLimit`（默认 20），输出 schema 加 `description`、`skills`、`jd_error`

### 阶段 2：技能词典（1 小时）

- `dsh-plugin/src/skills.js`：词典 + `extractSkills(text)` + `summarizeSkills(jobs)`
- 工具结果直接带 `skills` 与全局 `skill_summary`
- 单测：`dsh-plugin/tests/`（新建，用 node 直接跑断言，不依赖扩展环境）

### 阶段 3：报告生成（1 小时）

- 我拿到工具结果 → 写 `reports/boss-jobs-<时间>.md`
- 报告模板固定在插件 `docs/REPORT-TEMPLATE.md`，保证每次结构一致
- 长 JD 只摘要求段落进报告，全文留在工具结果里备查

### 阶段 4：验收（30 分钟）

- 当前页 40 条实跑，记录总耗时
- 人工抽查 3 条：JD 是否抓对、技能是否有噪音
- 回归：一期 37 项断言与薪资还原仍全过

## 五、验收标准

| 项 | 标准 |
| --- | --- |
| JD 采集成功率 | 本次采集的卡片里至少 85% 拿到 JD 全文 |
| 技能抽取 | 抽查 5 条，误报不超过 1 条 |
| 报告可用性 | 打开 md 能直接回答「这类岗位最看重什么、我该补什么」 |
| 兼容性 | `withDetail` 不传时行为与一期一致 |
| 安全 | 只读 DOM；单次点开条数有上限；失败可中断 |

## 六、风险与对策

| 风险 | 对策 |
| --- | --- |
| 详情面板选择器与列表不同、随版本变 | 阶段 0 先实测；选择器单独常量 + 多处回退 |
| 连续点开触发风控（薪资降级 / 验证码） | 800ms 节流、`detailLimit` 上限、失败即停 |
| JD 很长（2000 字以上）进上下文吃 token | 插件只返回 JD 全文一次；报告只摘要求要点 |
| 技能词表覆盖不全 | 报告里单独列「未归类的明显技能词」，方便后续补词 |
| 点开详情后列表位置变化 | 每次按 `job_id` 重新定位 |

## 七、不再做（相对 v2）

- 浏览器扩展的技能汇总区块与 CSV/JSON 字段扩展（扩展冻结在一期）
- 侧边栏分析视图
- 插件内接入 LLM 服务（由模型在读结果时归纳，不新增依赖）

## 八、复核修订约束（渔渔，2026-11-16）

以下条款用于消除原方案中的边界冲突，与原章节不一致时以本节为准。

### 8.1 详情面板操作口径

详情采集需要逐张 `click()` 卡片，会改变页面展示状态，因此不再笼统表述为“只读 DOM”。统一为：

- 不修改职位、公司等业务数据，不投递、不打招呼、不发送消息。
- 只允许通过点击打开和关闭详情面板，读取面板中用户可见的文本。
- 不自动滚动、不调用内部接口、不读取 Cookie 或隐藏响应。
- 每次按 `job_id` 重新定位卡片，并校验面板职位名，避免读到上一条。

### 8.2 失败处理与验收批次

统一失败策略：

- 单张 JD 读取失败：记录 `jd_error`，继续下一张。
- 连续 3 张失败：停止本批，并保留失败原因。
- 出现验证码、访问限制或需要人工处理的安全校验：立即停止，不再继续点击。

默认 `detailLimit=20` 不变。阶段 4 的“当前页 40 条实跑”改为**分两批，每批最多 20 条**，完整 JD 条数与尝试次数分别记录。

JD 采集成功率的分母只包括实际尝试打开详情的卡片，不包括未处理卡片。

### 8.3 JD 体积与输出方式

工具结果不得无限塞入完整 JD：

- 每条 JD 设置字符上限，超出部分截断并标记 `description_truncated`。
- 工具结果设置总字符上限，避免长 JD 挤占对话上下文。
- 完整原文保存到本地 JSON 文件，工具结果只返回文件路径、摘要、截断标记和计数。
- 报告模型需要核对原文时，按文件路径或 `job_id` 读取，不要求全文一次性进入对话。

输出 schema 同步增加：

- `description`
- `description_truncated`
- `skills`
- `jd_error`

`withDetail` 不传或传 `false` 时，工具输入、输出和行为与一期一致，不强制增加 JD 字段。

### 8.4 换机器可运行

当前 `dsh-plugin/index.js` 中默认宿主路径带本机绝对路径，不能仅凭“DSH 插件”认定便携性已完成。二期必须：

- 优先使用宿主注入的 `defineTool`。
- 将宿主工具包路径做成明确配置，保留 `DSH_TOOLS_ROOT` 覆盖方式。
- README 写清新机器安装、配置和启动步骤。
- 至少在一台不同环境验证：不修改源码即可运行。

若未完成跨环境验证，执行结果只能写“支持配置后迁移”，不能写“换机器即可用”。

### 8.5 薪资与技能统计口径

报告中的“薪资区间分布”需要结构化解析，新增：

- `salary_min`
- `salary_max`
- `salary_unit`
- `salary_unverified`

统计要求：

- `20-30K`、`40-70K·15薪`、`500-550元/天` 分开识别。
- 月薪与日薪分开统计，`·15薪` 不混入普通月薪区间。
- 未验证薪资不参与区间均值或分布计算。

技能频次按**提及该技能的去重岗位数**计算，不按关键词出现次数计算。注意 `Go`、RAG 等短词的词边界与别名归一，避免误报。

### 8.6 报告证据与结论边界

- 最看重的 5 项能力，每项至少附 1–2 个 `job_id` 或对应证据短句。
- 词典未覆盖、由模型归纳的技能单独标为“模型补充”，不与词典命中混算。
- 不得根据 JD 编造企业福利、团队情况、技术要求或用户能力缺口。
- “该补什么”改为“基于这批岗位高频要求给出的候选补齐方向”，不代表对个人能力的完整评估。
- 长 JD 只摘要求要点进报告，完整原文通过本地文件备查。

### 8.7 补充验收用例

除原有一期 37 项断言与薪资还原外，二期还需覆盖：

- 空 JD、超长 JD、连续失败、重复职位。
- 面板未切换、职位名不匹配、面板未关闭。
- 单条与总字符截断、原文文件可追溯。
- 月薪、日薪、未验证薪资混排时不混算。
- 模型补充技能有证据且单独标记。
- 新环境按文档配置后无需修改源码即可运行。
- 连续失败与验证码均按第 8.2 节停止，不会继续逐张点击。

## 九、独立复核结论（渔渔，2026-11-16 21:10）

当前状态：**changes_requested**。

一期 37/37 回归、JS 语法检查、核心技能/截断函数检查通过；原始数据证实 40/40 JD 成功、39 条技能分母、薪资分组正确。

但发现以下验收缺口：

1. 最终报告多项技能计数与 raw 不一致，需统一数据并加自动一致性断言。
2. `readDetail()` 未校验当前职位名，需防止导航失败时读入错误 JD。
3. 二期独立测试与 artifact manifest 不完整，需保留实际输出、文件大小、SHA-256 和读回证据。
4. 跨机器验证未做，只能声明“支持配置后迁移”，不能按“换机器即可用”验收。

完整证据见 `docs/review-v2.md`。修正后由渔渔进行第二轮针对性复核，通过项无需重复返工。
